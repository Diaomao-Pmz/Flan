# 04 决策记录

> 记录"为什么这样做"，防止以后把已否决的方案重新提出来。
> 格式：日期 · 决定 · 原因 · （否决了什么）。新的写在最上面。

---

### 近身反应：概率每掷一次就进全局冷却；反应招被打断 = 套路作废（2026-11-22）
- **决定**：从近身反应卡池挑到能出的招后掷一次骰，掷没掷中都进全局反应冷却（默认 2 秒）。反应招被打断和普通招一样作废整个套路，托管的弹幕照样发完。
- **原因**：每帧都检查，不进冷却的话概率 0.3 几帧之内就几乎必中，概率就没意义了；打断规则和现有的「打断一招 = 套路作废」保持一致。
- **否决**：每帧独立掷骰；只打掉反应招、套路接着走。

### 近身反应用「托管再取回」，在同一个出招协程里按顺序跑（2026-11-22）
- **决定**：反应时把站着放的弹幕交给发射器（托管），身体出反应招，打完按设置取回（回到 Boss 身上、开火时移动接着走）或直接做下一步。反应招内联在出招协程里，不另开协程。取回时「钉在原地」的弹幕也回到 Boss 身上发。反应期间已过脱手时间点 → 不取回，按脱手处理。走位中的反应只认「脱手 + 跟随 Boss」的弹幕（用户要求：钉在原地的弹幕不在 Boss 身边，不该让 Boss 反应）。
- **原因**：Boss 身体同一时间只做一招，打断时一刀切干净；跟随 Boss 时效果等同「两招都在身体层」。
- **否决**：反应招单独开协程、弹幕 Execute 照常等（交接笔记里的初版思路，两条协程打断时难收拾）。

### 脱手释放三合一，取代「接下一步的时机」和「为下一招靠位」（2026-11-22）
- **决定**：弹幕卡（默认）+ 套路步骤（覆盖）上的「脱手释放」：结束前 X 秒脱手、脱手时间（这段时间只走位不出招）、脱手后允许冲刺（允许 → 位移卡池只看冲刺；不允许 → 只走路，限制管到出下一招为止）、跟随 Boss / 钉在原地。旧的 `nextStepAfter`、`prepareNext / prepareLeadTime / prepareAllowDash` 删除，用到的套路（只有 `Test.asset`）要重配。
- **原因**：三个参数都在回答「弹幕放到什么时候 Boss 去做下一件事、那段路怎么走」，分开配容易互相打架。
- **否决**：保留三套参数各管一段。

### 弹幕层规则表：按卡类型判断，被拦就等（2026-11-22）
- **决定**：弹幕层有弹幕时，下一张卡按 `BossAIDecider` 的规则表（默认弹幕 / 近战 / 冲刺 ✓，特殊近战 / 特殊远程 / 传送 ✗）决定能不能出；卡上 `whileBarrage` 可单独改允许 / 禁止。被拦的卡不跳过、不作废，**等弹幕发完**，等的时候照常走位、不算靠位超时；候补招式按原规则选出后被拦也是等，不改看下一个候补。
- **原因**：边放弹幕边瞬移 / 放激光太难躲；按类型自动判断，不用每张卡都配。

### Boss 的手感控制交给套路逐步配置，不交给 AI 随机（2026-11-22）
- **决定**：开火时移动、脱手释放、近身反应都是「卡上放默认值 + 套路步骤可以覆盖（跟随卡 / 自己选）」。
- **原因**：会给玩家造成负担的决定（冲不冲刺、要不要同时放招）用户要自己在套路里配。

### 开火时移动三种：站定 / 保持距离 / 位移后站定（2026-11-22）
- **决定**：保持距离 = 每次出招按「范围 + 偏向」抽一个距离、全程保持（±0.2 格算到位）；位移后站定 = 出招时定方向（远离或靠近玩家），走够格数就停。外加移速倍率。射程仍是出手前提。
- **否决**：「走到距离后站定」（用户删掉了）。

### 冲刺卡和位移卡池：传送和冲刺都能放；Boss 的终点判定自己写一份（2026-11-22）
- **决定**：新增纯位移的 `DashMoveNode`（有冷却），位移卡池和套路步骤都能用。Boss 的 `BossDashEndpointGuard` 不复用玩家的 `DashEndpointGuard`。位移卡池抽卡一律看冷却（套路步骤里的卡不看冷却但会记冷却）。
- **原因**：玩家和 Boss 的代码分开写（11-21 的规矩）。

### 套路后续招式间隔：最后一招放完才开始算（2026-11-22）
- **决定**：`BossRoutine.restAfter` 从最后一招真正放完（或脱手）那一刻开始计时，被打断不算；计时期间不选新套路，单招和位移照常。

### 破盾值：整招总量，第一次打中一次扣完（2026-11-22 完成）
- **决定**：近战招填整招的破盾值，多段判定只在第一次打中时扣一次；子弹按发数平分；激光按每跳。没填（-1）按老规矩近战 100 / 远程 3。
- **原因**：多段判定每段都扣会让三段判定的招一下破掉 300 的盾。

### 子弹伤害按整招总量填，平分到每颗（2026-11-21）
- **决定**：ComboNode 填「子弹总伤害」，按连射发数平分（余数给前几颗）；0 = 每颗用预制体伤害。
- **原因**：为了表现，有些技能会放很多子弹，伤害不该随子弹数翻倍。
- **否决**：每颗子弹各自覆盖伤害（旧做法）。

### 破盾走 B 方案：每招单独填破盾值（2026-11-21 定方向，11-22 完成，见上）
- **决定**：招式（和子弹）单独填「破盾值」，跟伤害分开；没填的按现在的近战 100 / 远程 3。
- **原因**：每招擅不擅长破盾是独立属性，和蓄力三段各有定位、以后流派 build 改数值的思路一致。
- **否决**：A（破盾 = 伤害 × 近战 / 远程倍率，伤害和破盾绑死）、C（保持只分近战 / 远程）。

### 玩家和 Boss 的同类功能分开写（2026-11-21）
- **决定**：玩家激光写成独立的 `LaserSpecial`，不和 Boss 的 `BAE_LaserAttacker` 抽公共模块。
- **原因**：用户要分清哪部分代码是玩家的、哪部分是 Boss 的，改一边不怕影响另一边。
- **否决**：原计划（待定事项 01）把激光判定 / 绘制抽成双方共用的 `LaserBeam`。

### 特殊招用「招式类型 + 插槽」，而不是每种招一个新节点类（2026-11-21）
- **决定**：ComboNode 加 `moveType`，选特殊类型时在 `[SerializeReference]` 插槽里挑一个效果（像 Boss 弹幕图案的下拉），参数填在 ComboNode 上。时间（前摇 / 判定 / 后摇）仍跟节拍总表。
- **原因**：以后加特殊招只写一个派生类；连段、蓄力、打断这些通用设置不用复制。

### 激光：首跳带打断 / 击退，每跳都推（2026-11-21）
- **决定**：第一跳带 breakMask / 受击反应 / 击退 / 硬直；每跳都带一个短暂的持续推力（`bossPushSpeed`），Boss 被激光顶着慢慢后移。前摇保留预警线；默认被墙挡（用障碍图层控制，不单独做「穿墙」开关）；开火后不转身。
- **否决**：每跳都击退（会把 Boss 弹飞）、「穿墙」勾选框。

### 配置重复一律报错、都不生效（2026-11-21）
- **决定**：节拍总表同一招在两行、双蓄配方等级总和重复，都在 Console 报错并让重复的都失效。
- **原因**：用户原话「直接报错，到时候我自己调」；悄悄「以前面的为准」会让人以为改了没生效。
- **否决**：前面那条生效。

### 节拍总表不再按名字自动绑定（2026-11-21）
- **决定**：每行自己选招式，只在 Reset 时按名字找一次。
- **原因**：资产改名 / 复制（比如 L_2 名字还是 BB3）会被错绑到别的行。

### 消弹做成通用多选（2026-11-21）
- **决定**：`bulletCancel` 多选：子弹 / 近战判定 / 位移，任何招都能勾。位移消弹期间同时免疫子弹伤害；子弹消弹持续到打中 Boss 或出屏。
- **原因**：用户想让 AA2（突进）和 BB2（远程）都能消弹，而且以后别的招也可能要。近战判定消弹留到以后做。

### 跳跃按高度配置（2026-11-21，用户选的方案 3）
- **决定**：填最大高度、最小高度、松手剩余速度、下落重力倍率；起跳速度反推。默认值保持原手感（最大高度 2.87）。
- **原因**：和冲刺 / 滑铲「填距离 + 时长」同一个思路：填结果比填力 / 速度直观。
- **否决**：继续填 jumpForce（保留为隐藏字段，只做属性比例基准）。

### 蓄力减速做成渐变（2026-11-21）
- **决定**：移速、跳跃各有「起始值 → 终值」，渐变时长 -1 = 跟起蓄时间；起蓄时间按招配置。
- **原因**：起蓄那一下突然变慢手感生硬。

### 抢拍阶段用「前摇 / 判定 / 后摇」多选，按招配置（2026-11-21）
- **决定**：节拍总表每招一个 `switchCutPhases`（`[Flags] AttackPhaseMask`），默认只勾后摇。没勾的阶段里按的下一招先缓存，到勾了的阶段自动打出。
- **原因**：游戏支持玩家自己 build 流派，以后要做战斗模组系统；做成多选位掩码，模组直接改这个值就行，不用改代码。
- **否决**：两选项下拉框（「仅后摇 / 前摇和后摇」）。

### 拼刀：按位掩码选能拼哪类招，所有拼刀只结束 Boss 当前这一招（2026-11-21）
- **决定**：`clashMask`（和 breakMask 同款的 ActionCategory 多选）+ 成功后位移 `clashThrust`(X,Y)+时长+穿过开关。拼刀一律只结束 Boss 当前这一招，套路继续；要打断整个套路靠 breakMask。裁判在 Boss 一侧（Boss 出判定前查玩家登记的拼刀框）。
- **否决**：`ClashEffect` 两选项（打断套路 / 只打断单招）下拉、固定的「拼刀后退距离」。

### Boss 受击反应由 Boss 自己决定（2026-11-21）
- **决定**：玩家只在 DamageInfo 里写意图（breakMask、击退距离、hitStun）；Boss 判断：正在出招且能打断 → 打断；击退 / 硬直只在 Boss 没在出招或被打断时生效（霸体出招不吃击退）。
- **原因**：沿用 DamageInfo「攻击方表达意图，受击方决定反应」的契约。

### 位移终点与 Boss 重叠：按穿过比例决定停面前还是穿身后（2026-11-21）
- **决定**：每个物理帧用射线对「Boss 碰撞框外扩玩家半个身位」的盒子求交，终点会落在 Boss 里时，穿过比例 ≥ 0.5 就穿到身后，否则停在面前；容差 0.1。动作时长不变。
- **原因**：参考同类 2D 动作游戏的宽松处理；Boss 也在动，所以每帧重算而不是出发时算一次。

### Boss 近战的蓄刀时长：出招时一次抽好，不做周期判定（2026-11-21）
- **决定**：`holdTime` 是上限，出招时按 `releaseBias`（0～1，越大越偏长）抽一个时长。
- **否决**：每隔 n 秒判定一次要不要出刀、「从挥砍开始算」的判定范围（改为从 attack 开始算）。

### 特效由场景里的 EffectManager 统一管理，表里接预制体（2026-11-17）
- **决定**：所有角色特效配在一张表上（预制体 + 参数），招式特效按动画 PlayEffect 时间戳触发，蓄力光效按「武器 + 等级」挂上 / 收回。管理器自己按预制体分池。
- **原因**：原来特效散在招式和武器上、由对象池固定时长播放，蓄力光效没地方配；集中一张表好调。接预制体而不是 Sprite，是为了复用已有的特效资产，不用重做。
- **否决**：表里接 Sprite；继续用 `PooledEffect` 固定时长。

### 特效存活：四种模式，Fixed 就是播完一遍（2026-11-17）
- **决定**：`FollowActive / FollowAttack / Fixed / UntilMarker`。动作内就结束的特效用 `EffectEnd` 时间戳标记结束；比动作长的用 Fixed（播完预制体自己的动画一遍，不手填时长）或把 EffectEnd 打在后摇之后。`Fit Duration` 勾选 = 调倍速让特效动画在存活时间里正好播完一遍。
- **否决**：手填 Lifetime（已删掉这一栏）。

### 人物动画按三段各自调速，不掐断（2026-11-17，方案 A）
- **决定**：前摇 / 攻击 / 后摇三段各算一个倍速，正好在填的时长里播完；动画事件按同一套换算对到实际时间。
- **原因**：之前填的时长只是「到点就掐断」，动画、特效、判定会对不上；用户的理解本来就是「动画按填的时间乘倍速播放」。

### 时长、窗口、动画与位移集中到「节拍总表」（2026-11-17）
- **决定**：新建 `AttackTimingConfig`（节拍总表），ComboNode 上的连段窗口、三段时长、动画与表现、Aim Dash 全部搬过去并从 ComboNode 删掉（旧值隐藏保留，供自动搬运）。平a / 蓄力 12 招固定标题，双蓄 5 个槽拖招式选。
- **原因**：调手感时要来回点十几个招式资产；集中一张表方便对比。双蓄要复用已有招式，所以用选框。

### 出招位移 = 精确距离、匀速、可选起步阶段（2026-11-17）
- **决定**：`forwardThrust` 填的是**距离**，从所选阶段（Windup / Active / Recovery）开头起步匀速走完，时长默认等于该阶段；被打断就停在半路。蓄力位移（Aim Dash）同样是距离，固定从判定段开始。
- **否决**：按速度推、和判定开始强制对齐。

### 删除动量系统，滑铲攻击作废（2026-11-17，文件 11-20 删完）
- **决定**：`PlayerMomentum`（动量池）和 `SlideMomentum`（跨状态横向动量）整套删除。
- **原因**：用户不想要这套系统；滑铲攻击暂时不做。以后要做滑铲攻击需要重新设计，不要把这两个文件找回来直接用。

### 冲刺 / 滑铲在物理帧里计时（2026-11-17）
- **决定**：冲刺 / 滑铲的计时和推进都放在 FixedUpdate，最后一个物理帧只走剩下的距离。
- **原因**：原来在画面帧里倒计时，停下前物理引擎会多跑几步，30 帧时冲刺平均多走 12%。

### 平a后两只手都能蓄力；「刚放完蓄力」按手分别记（2026-11-17）
- **决定**：删掉「平a后只能一只手蓄力」；两只手的起步等级都按当前段数。「这只手刚放完蓄力、之后还没打过平a」用动作序号按手分别判断，另一只手放蓄力不影响这只手。
- **原因**：那条规则让平a之后永远打不出双蓄，还把第二只手的长按变成一发平a、改掉段数；共用的判断让先打的平a在蓄力放出后失去「平a后接蓄力」加速。双蓄规则以后再定。

### 攻击由"时间表"驱动，不再由动画事件驱动（2026-11）
- **决定**：出招时读出动画剪辑里各事件的时间点，生成攻击实例自己掐表执行；动画事件入口方法留空壳。
- **原因**：换手可以顶掉动画但不该打断上一招的判定 / 子弹；一招要分前摇 / 判定 / 后摇分别决定能不能移动。两者都要求逻辑不依赖动画是否还在播。
- **附带**：时间点仍然来自动画事件，美术改动画不用另外配时间；`MarkAttackEnd` 事件标记判定段结束。

### 蓄力等级跟连段深度走，上限靠按键主动提高（2026-11）
- **决定**：平a后接蓄力从"当前连段深度"那一级起步（0.3 秒），并停在这一级；侧键每按一下上限 +1（3 之后回 1）。原地起手固定 1 级、1 秒。蓄力放完后段数跟最后一发平a走。
- **否决**：R2"只能接同手同深度"、R6"蓄力后段数跟蓄力等级走"、蓄力等级自动循环升级、空中蓄力悬停（整套删除）。
- **注意**：这推翻了批次 J 里"否决连段深度决定蓄力等级"的结论。

### ~~平a后只能一只手蓄力（2026-11-16）~~ —— **已于 2026-11-17 推翻**，见上
- 原决定：平a后两只手一起长按，只有先起蓄的手蓄力，另一只手的长按当作平a。

### 冲刺 / 滑铲按「距离 + 时长」配置（2026-11-16）
- **决定**：配置里填距离和时长，速度反推；冲刺速度加成只改用时，不改距离。
- **原因**：策划和动画关心的是位移多远、用多久（要和动画长度对齐），速度只是结果。
- **否决**：「速度 + 距离」（试验版用过）、「速度 + 时长」（最早的做法）。

### 不做自动化测试，先保证解耦；验证靠逐帧回看（2026-11-16）
- **决定**：规则还在变，暂不搭自动化连招测试。提供调试面板 + 逐帧回看（录最近 10 秒状态，暂停后往回翻）。
- **原因**：战斗节奏快，肉眼实时看不出问题；录下来慢慢翻成本最低。

### 脚本里只留代码相关的注释（2026-11-16）
- **决定**：设计理念、比喻、历史记录不写进脚本，放设计文档。

### 宝石用"三态裁决 + 修饰器"，不在状态机里按宝石类型分支（V0.2）
- **决定**：每颗装备的宝石在动作触发时返回 `Normal / Override / Reject`；属性变化用带来源标签的修饰器贴在不可变基础值上。
- **原因**：状态卡带只依赖宝石接口，加新宝石不改旧代码；装 / 卸天然对称，根除"卸了宝石效果还在"的幽灵宝石 bug。
- **否决**：在状态里 `if (gem == Echo)` 分支；直接改写属性值。

### 输入宽恕分三层，派发结果分三态
- **决定**：攻击的缓存窗口锚定在自身动画的取消窗口；蓄力按住无过期；位移指令从按键起给一个短固定窗口。派发结果 `Success / Retry / Rejected`。
- **原因**：曾出现"蓄力中按 Shift，冲刺在 CD → 缓存 → CD 好了以普通冲刺兑现，打断蓄力"的 bug。被故意拒绝的指令必须丢弃，不能几帧后"借尸还魂"。

### 蓄力"松手才放、按等级选招"（批次 J）
- **决定**：去掉"蓄够自动放"，改为松手时在 ≤ 当前等级的招里挑最高的。
- **否决并删除**：连放惩罚（弱化版蓄力）、"连段深度决定蓄力等级"两套机制。蓄力也不再是状态机的一个状态（`chargeState` 已删除，由 `PlayerChargeSystem` 随身模块接管）。

### 动画事件不能是唯一生命线（批次 L）
- **决定**：`ComboState` 加兜底超时（动画长度 × 倍率）。
- **原因**：动画重做后 A1/B1 因漏配 `OnAttackAnimationEnd` 全部卡死且无报错。

### Boss 用加权抽卡 + 意图预留
- **决定**：招式是 SO 卡（权重、冷却、射程），抽中够不着的卡就预留为"意图"，让 Boss 走过去，而不是重抽。
- **原因**：整场战斗在 Inspector 里调参，不改代码；走位由"下一招需要什么"决定。

### Boss 执行器用类型注册表派发
- **决定**：执行器按自己处理的卡类型注册，反射发现，派发是字典查表；接口强制 `Cancel()`。
- **原因**：新招式 = 一个资产 + 一个组件，零修改旧文件；破盾 / 转阶段可以一次性打断所有执行器。

### 伤害契约统一为 `DamageInfo`（2026-08-07）
- **决定**：敌我都走 `IDamageable.TakeDamage(in DamageInfo)`。击退默认归受击方决定，招式可以 `overrideKnockback`。
- **原因**：原来玩家侧没有近战 / 远程维度，以后做"护盾只挡远程""弹反只对近战"得推倒重来。

### 对象池 key 由对象自己记住（2026-08-07）
- **决定**：`Recycle(gameObject)` 单参数；key 找不到时报错而不是静默返回。
- **原因**：两份真相（发射器配置的 key / 回收时手写的 key）导致子弹静默泄漏。

### 暂时"0 血不死"
- **决定**：`DeadState` 写好但不接线，按用户要求维持 0 血不死（方便调试）。接线点都标了 TODO。

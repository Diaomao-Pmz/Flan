# 04 决策记录

> 记录"为什么这样做"，防止以后把已否决的方案重新提出来。
> 格式：日期 · 决定 · 原因 · （否决了什么）。新的写在最上面。

---

### 特效由场景里的 EffectManager 统一管理，表里接预制体（2026-11-17）
- **决定**：所有角色特效配在一张表上（预制体 + 参数），招式特效按动画 PlayEffect 时间戳触发，蓄力光效按「武器 + 等级」挂上 / 收回。管理器自己按预制体分池。
- **原因**：原来特效散在招式和武器上、由对象池固定时长播放，蓄力光效没地方配；集中一张表好调。接预制体而不是 Sprite，是为了复用已有的特效资产，不用重做。
- **否决**：表里接 Sprite；继续用 `PooledEffect` 固定时长。

### 特效存活：四种模式，Fixed 就是播完一遍（2026-11-17）
- **决定**：`FollowActive / FollowAttack / Fixed / UntilMarker`。动作内就结束的特效用 `EffectEnd` 时间戳标记结束；比动作长的用 Fixed（播完预制体自己的动画一遍，不手填时长）或把 EffectEnd 打在后摇之后。`Fit Duration` 勾选 = 调倍速让特效动画在存活时间里正好播完一遍。
- **否决**：手填 Lifetime（已删掉这一栏）。

### 人物动画按三段各自调速，不掐断（2026-11-17，方案 A）
- **决定**：前摇 / 攻击 / 后摇三段各算一个倍速，正好在填的时长里播完；动画事件按同一套换算对到实际时间。
- **原因**：之前填的时长只是「到点就掐断」，动画、特效、判定会对不上；用户的理解本来就是「动画按填的时间乘倍速播放」。

### 时长、窗口、动画与位移集中到「节拍总表」（2026-11-17）
- **决定**：新建 `AttackTimingConfig`（节拍总表），ComboNode 上的连段窗口、三段时长、动画与表现、Aim Dash 全部搬过去并从 ComboNode 删掉（旧值隐藏保留，供自动搬运）。平a / 蓄力 12 招固定标题，双蓄 5 个槽拖招式选。
- **原因**：调手感时要来回点十几个招式资产；集中一张表方便对比。双蓄要复用已有招式，所以用选框。

### 出招位移 = 精确距离、匀速、可选起步阶段（2026-11-17）
- **决定**：`forwardThrust` 填的是**距离**，从所选阶段（Windup / Active / Recovery）开头起步匀速走完，时长默认等于该阶段；被打断就停在半路。蓄力位移（Aim Dash）同样是距离，固定从判定段开始。
- **否决**：按速度推、和判定开始强制对齐。

### 删除动量系统，滑铲攻击作废（2026-11-17，文件 11-20 删完）
- **决定**：`PlayerMomentum`（动量池）和 `SlideMomentum`（跨状态横向动量）整套删除。
- **原因**：用户不想要这套系统；滑铲攻击暂时不做。以后要做滑铲攻击需要重新设计，不要把这两个文件找回来直接用。

### 冲刺 / 滑铲在物理帧里计时（2026-11-17）
- **决定**：冲刺 / 滑铲的计时和推进都放在 FixedUpdate，最后一个物理帧只走剩下的距离。
- **原因**：原来在画面帧里倒计时，停下前物理引擎会多跑几步，30 帧时冲刺平均多走 12%。

### 平a后两只手都能蓄力；「刚放完蓄力」按手分别记（2026-11-17）
- **决定**：删掉「平a后只能一只手蓄力」；两只手的起步等级都按当前段数。「这只手刚放完蓄力、之后还没打过平a」用动作序号按手分别判断，另一只手放蓄力不影响这只手。
- **原因**：那条规则让平a之后永远打不出双蓄，还把第二只手的长按变成一发平a、改掉段数；共用的判断让先打的平a在蓄力放出后失去「平a后接蓄力」加速。双蓄规则以后再定。

### 攻击由"时间表"驱动，不再由动画事件驱动（2026-11）
- **决定**：出招时读出动画剪辑里各事件的时间点，生成攻击实例自己掐表执行；动画事件入口方法留空壳。
- **原因**：换手可以顶掉动画但不该打断上一招的判定 / 子弹；一招要分前摇 / 判定 / 后摇分别决定能不能移动。两者都要求逻辑不依赖动画是否还在播。
- **附带**：时间点仍然来自动画事件，美术改动画不用另外配时间；`MarkAttackEnd` 事件标记判定段结束。

### 蓄力等级跟连段深度走，上限靠按键主动提高（2026-11）
- **决定**：平a后接蓄力从"当前连段深度"那一级起步（0.3 秒），并停在这一级；侧键每按一下上限 +1（3 之后回 1）。原地起手固定 1 级、1 秒。蓄力放完后段数跟最后一发平a走。
- **否决**：R2"只能接同手同深度"、R6"蓄力后段数跟蓄力等级走"、蓄力等级自动循环升级、空中蓄力悬停（整套删除）。
- **注意**：这推翻了批次 J 里"否决连段深度决定蓄力等级"的结论。

### ~~平a后只能一只手蓄力（2026-11-16）~~ —— **已于 2026-11-17 推翻**，见上
- 原决定：平a后两只手一起长按，只有先起蓄的手蓄力，另一只手的长按当作平a。

### 冲刺 / 滑铲按「距离 + 时长」配置（2026-11-16）
- **决定**：配置里填距离和时长，速度反推；冲刺速度加成只改用时，不改距离。
- **原因**：策划和动画关心的是位移多远、用多久（要和动画长度对齐），速度只是结果。
- **否决**：「速度 + 距离」（试验版用过）、「速度 + 时长」（最早的做法）。

### 不做自动化测试，先保证解耦；验证靠逐帧回看（2026-11-16）
- **决定**：规则还在变，暂不搭自动化连招测试。提供调试面板 + 逐帧回看（录最近 10 秒状态，暂停后往回翻）。
- **原因**：战斗节奏快，肉眼实时看不出问题；录下来慢慢翻成本最低。

### 脚本里只留代码相关的注释（2026-11-16）
- **决定**：设计理念、比喻、历史记录不写进脚本，放设计文档。

### 宝石用"三态裁决 + 修饰器"，不在状态机里按宝石类型分支（V0.2）
- **决定**：每颗装备的宝石在动作触发时返回 `Normal / Override / Reject`；属性变化用带来源标签的修饰器贴在不可变基础值上。
- **原因**：状态卡带只依赖宝石接口，加新宝石不改旧代码；装 / 卸天然对称，根除"卸了宝石效果还在"的幽灵宝石 bug。
- **否决**：在状态里 `if (gem == Echo)` 分支；直接改写属性值。

### 输入宽恕分三层，派发结果分三态
- **决定**：攻击的缓存窗口锚定在自身动画的取消窗口；蓄力按住无过期；位移指令从按键起给一个短固定窗口。派发结果 `Success / Retry / Rejected`。
- **原因**：曾出现"蓄力中按 Shift，冲刺在 CD → 缓存 → CD 好了以普通冲刺兑现，打断蓄力"的 bug。被故意拒绝的指令必须丢弃，不能几帧后"借尸还魂"。

### 蓄力"松手才放、按等级选招"（批次 J）
- **决定**：去掉"蓄够自动放"，改为松手时在 ≤ 当前等级的招里挑最高的。
- **否决并删除**：连放惩罚（弱化版蓄力）、"连段深度决定蓄力等级"两套机制。蓄力也不再是状态机的一个状态（`chargeState` 已删除，由 `PlayerChargeSystem` 随身模块接管）。

### 动画事件不能是唯一生命线（批次 L）
- **决定**：`ComboState` 加兜底超时（动画长度 × 倍率）。
- **原因**：动画重做后 A1/B1 因漏配 `OnAttackAnimationEnd` 全部卡死且无报错。

### Boss 用加权抽卡 + 意图预留
- **决定**：招式是 SO 卡（权重、冷却、射程），抽中够不着的卡就预留为"意图"，让 Boss 走过去，而不是重抽。
- **原因**：整场战斗在 Inspector 里调参，不改代码；走位由"下一招需要什么"决定。

### Boss 执行器用类型注册表派发
- **决定**：执行器按自己处理的卡类型注册，反射发现，派发是字典查表；接口强制 `Cancel()`。
- **原因**：新招式 = 一个资产 + 一个组件，零修改旧文件；破盾 / 转阶段可以一次性打断所有执行器。

### 伤害契约统一为 `DamageInfo`（2026-08-07）
- **决定**：敌我都走 `IDamageable.TakeDamage(in DamageInfo)`。击退默认归受击方决定，招式可以 `overrideKnockback`。
- **原因**：原来玩家侧没有近战 / 远程维度，以后做"护盾只挡远程""弹反只对近战"得推倒重来。

### 对象池 key 由对象自己记住（2026-08-07）
- **决定**：`Recycle(gameObject)` 单参数；key 找不到时报错而不是静默返回。
- **原因**：两份真相（发射器配置的 key / 回收时手写的 key）导致子弹静默泄漏。

### 暂时"0 血不死"
- **决定**：`DeadState` 写好但不接线，按用户要求维持 0 血不死（方便调试）。接线点都标了 TODO。

## 踩坑备忘（Unity 相关）

- **P4 编码必须是 UTF-8**：服务器是 Unicode 模式，P4V 默认用系统编码（中文 Windows = CP936 GBK），会把 UTF-8 的中文注释当 GBK 转换存进服务器，变成乱码。提交时报 "Translation of file content failed" 就是这个信号（11-26）。
- **`[SerializeReference]` 列表点「+」只复制引用**：新元素和上一个元素指向同一份参数，改一个另一个跟着变（普通字段不受影响）。已在 `BulletNode`、`BossCinematic` 的 `OnValidate` 里自动拆开；以后新加 `[SerializeReference]` 列表也要调 `SerializeReferenceDedup`。临时绕过：在新元素的下拉框里重选一次类型。
- **挪文件夹时连 .meta 一起挪**：只挪 .cs 会让 Unity 生成新 guid，资产上就是 Missing Script。修法：把新 .meta 的 guid 改回旧的（旧 guid 可从资产的 `m_Script` 里查）。
- **（Claude 工作流程）写回文件后要核对**：在 outputs 里刚写完马上提交，有可能提交的是改之前的副本（11-26 发生过一次）。写完等十几秒再提交，提交后重新读回来和输出逐字节比对。
- **Git：合并 / stash pop 之后先查冲突标记再提交**：`git grep -l "<<<<<<<" -- Assets`。冲突标记会出现在 `.anim`、`.asset`、`.unity`、`.meta` 里，Unity 不一定报错（`.meta` 里有两个 guid 时 Unity 可能直接换新 guid，引用就断了）。GitHub Desktop 切分支时会自动 stash，pop 失败的冲突会被一起提交。
- **Git 合并会「悄悄」换回旧版**：没有冲突标记的文件也可能被合并成另一边的旧内容。判断方法：和合并前的版本逐文件比对（`git diff --name-status -M 旧提交 新提交`）。
- **找回没有分支指向的提交**：`git fsck --no-reflogs --unreachable`，GitHub Desktop 的 stash 提交信息以 `!!GitHub_Desktop<分支名>` 开头。
- **删 MonoBehaviour 脚本前先查预制体 / 场景有没有挂它**：拿 `.meta` 里的 guid 去 `git grep -l <guid> -- "*.unity" "*.prefab"`，有就先在 Unity 里 Remove Component，否则留下 Missing Script。
- **按时间推进的位移放 FixedUpdate**，最后一步只走剩下的量；在 Update 里倒计时、在物理帧里给速度，距离会随帧率变化。

- **MonoBehaviour 类名必须和文件名一致**，否则 Add Component 里搜不到（`AttackTimelineRunner` 曾写在 `AttackTimeline.cs` 里，只能靠运行时补挂）。
- **删"兜底"之前先确认它确实不再被触发**：曾根据回归清单的结果推断 prefab 已挂组件，删掉运行时补挂后整套攻击 / 冲刺 / 滑铲空引用。
- 改 SO 字段名时加 `[FormerlySerializedAs("旧名")]`，已配置的值才不会丢。

- Unity 只调用最派生类上的 `Awake`：基类 `Awake` 必须 `protected virtual`，派生类 `override` 并调用 `base.Awake()`。
- `Destroy(Component)` 延迟到帧末才执行，池化对象同帧重新借出会拿到"脏"组件。
- `Start()` 一生只跑一次：池化对象的初始化放 `Configure()` / `OnSpawn`，不要放 `Start()`。
- SO 资产运行时写字段：编辑器里会污染资产，打包后所有实例共享。
- `BulletAcceleration` 必须手动挂在 `EnemyBullet` 预制体上，否则加速弹失效。

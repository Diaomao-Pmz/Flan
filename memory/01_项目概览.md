# 01 项目概览

> 最后核对：2026-11-21 晚（文件夹结构按用户 11-21 在 Unity 里重新整理后的样子）

## 基本信息

- **类型**：2D 动作平台游戏（近战连招 + 远程射击 + 飞行 + Boss 弹幕战）
- **主角**：芙兰（Flandre），代码命名空间 `Flandre.CombatSystem`
- **引擎**：Unity `6000.3.1f1`
- **规模**：约 146 个 C# 脚本、约 2 万行（玩家约 1.15 万行，Boss/敌人约 5.5 千行）
- **仓库**：`https://github.com/Diaomao-Pmz/Flan`，本地 `D:\Unity project\Flan`

## 和用户协作的规矩（2026-11-21 总结）

- **改文件前先说明**：先从功能角度说这次要实现什么，再说代码怎么改、改哪些文件；**等用户确认后再动手**。改完列出每个文件的路径（含新文件）。解释架构时多用比喻。
- **记忆库由 Claude 维护**：对话中自己总结规律，**用户说「整理 memory base」时统一写进 memory/**，平时不单独改记忆库。
- **玩家和 Boss 的同类功能分开写，不共用代码**（11-21 用户要求，例：玩家激光 `LaserSpecial` 和 Boss 的 `BAE_LaserAttacker` 各写各的），方便分清哪部分是谁的。通用的编辑器工具可以参考，但不跨过去改 Boss 文件。
- **配置重复 → 直接报错、都不生效**，不要"以前面的为准"（用户原话：到时候我自己调）。节拍总表同一招拖进两行、双蓄配方等级总和重复都按这条处理。
- **新参数的默认值要保证现有手感不变**；用 `-1` 表示"跟随 / 自动"（比如时间填 -1 = 跟动画事件走，渐变时长 -1 = 跟起蓄时间）。
- **参数填"结果"而不是"手段"**：高度、距离、时长，而不是力、速度（冲刺 / 滑铲、跳跃都已经这样改了）。
- **Inspector 保持简洁**：按招式类型 / 开关隐藏用不上的栏位（隐藏 ≠ 不生效，要在提示里讲清楚）。
- 用户会问"业界一般怎么做"，回答时给出几种做法的对比和推荐理由。

### 文件写回的流程（这个会话环境下）
- 没有可用的 device shell：用 `device_stage_files` 读 → 在工作区改 → 放到 `/mnt/user-data/outputs/` → **等 15～20 秒**再 `device_commit_files`（带 expectedMtimeMs）→ **再 stage 一次逐字比对**。
- **11-21 踩过坑**：改完马上写回，写回工具读到的是还没同步的旧副本，结果把改动前的内容（还变成了 LF 换行）写回了用户电脑。所以一定要等、一定要核对。
- 保持原文件格式：脚本基本都是 **UTF-8 无 BOM + CRLF**；例外：`Enemies/Boss/BossLogic/BossController.cs` 有 BOM。
- **读不到深层文件**：读文件的工具（staging）最多只能读到连接文件夹往下 **7 层**目录里的文件，这是工具本身的限制，和权限无关（列目录能看到、但读不了）。连接的是项目根目录 `D:\Unity project\Flan`，所以 `Assets/Scripts/Player_V0.2/1_Config/P_Combonodes/super/Skills/Lasers/` 里的文件（第 8 层）读不到。解决办法：请用户在桌面端额外连接一个更深的文件夹（比如 `P_Combonodes`），或者把文件挪浅一层；不行就看截图。11-21 用户说读不到就算了。
- 没有 Unity，只能做语法检查（tree-sitter-c-sharp），**每次都要提醒用户打开 Unity 看 Console**。

# 施工方案与改动记录

## 关键底层改动：攻击逻辑由「动画事件驱动」改为「时间表驱动」
**问题**：判定框（PlayerHitDetection.TriggerAttackHitbox）、子弹（PlayerWeaponEmitter.SpawnProjectile）、特效（PlayerEffectSpawner.PlayEffect）都由动画事件触发，且都读 `ComboInputBuffer.currentNode`。动画一被顶掉，未触发的事件永远不发生；ComboState.Exit 还会 ForceStopHitbox / CancelBurst。
→ R5「只打断动画、不打断逻辑」和 R1「按前摇/判定/后摇分阶段」都做不到。

**改法**：出招时从 `node.attackClip.events`（运行时可读）提取 TriggerAttackHitbox / SpawnProjectile / PlayEffect 的时间点，生成一张时间表，由独立的「攻击实例」自己掐表执行，不依赖动画是否还在播。
- 前摇 = 第一个出刀/出弹事件之前；判定 = 判定窗口与连射持续期；后摇 = 之后（剩余动画 + recoveryTime）。
- 判定框与连射改为可同时跑多份（每份自带命中名单、自带 node/weapon 快照）。
- 原动画事件入口保留为空操作（避免 Unity 报 "no receiver"），OnAttackAnimationEnd 可继续作为结束信号或改用 clip.length 计时。
- 用户**无需重新配置任何时间**。

#### 需要用户动手的地方
- **双蓄配方表是空的**，所以现在双手先后松手一律按两发单蓄力处理。要出强化招：先做强化招的 ComboNode（需要动画），再建 DualChargeRecipe 资产，拖进玩家 WeaponLoadout 的 Dual Charge Recipes。
- 动画上的 TriggerAttackHitbox / SpawnProjectile / PlayEffect 事件**不要删**，时间点仍从它们读。

#### 规则没覆盖到、自行决定的地方（请过目）
1. **前摇里"方向键移动"只认出招之后新按下 / 换向的方向键**；后摇里按着就算。原因：按着方向键跑动中出招是常态，若按着就算移动，每一招都会在前摇被自己取消。只看左右，上下不算（上下是方向变招 / 瞄准用的）。
2. **"判定中"按全部在跑的判定算**：动画已被顶掉、逻辑还在跑的旧招只要还在判定，移动 / 跳 / 飞就无效。
3. **判定和连射不会拖到招式自然长度之外**：A1 的 hitboxDuration = 0.5 比动画剩余时间长，旧版靠"动画结束强停"截断，现在在动画长度处截断，未被打断时手感与旧版一致。
4. **前摇被移动取消后这只手立刻可用**（R1 只写了连段归零，没写手的状态）。
5. **冲刺 / 滑铲期间连段窗口暂停计时**（否则 A1 的 0.35s 窗口会在冲刺途中过期，违背"永不打断连段"）；不在攻击动画里时冲刺 / 滑铲同样免掉剩余后摇。
6. **换手抢拍保持旧节奏**：被另一只手顶掉动画的那只手，从被顶掉那一刻起只算 recoveryTime（R1 的「剩余动画 + recoveryTime」只用于被移动取消的情况）。
7. **蓄力循环的时间轴**：进入某级后再等多久到下一级 = 1→2 等 1.0s、2→3 等 1.0s、3→1 等 0.5s，起步的 0.3s 计入进度。例：原地起手 1 级@0.3s → 2 级@1.0s → 3 级@2.0s → 1 级@2.5s；A2 后 2 级@0.3s → 3 级@1.0s → 1 级@1.5s；A3 后 3 级@0.3s → 1 级@0.5s → 2 级@1.5s。
8. **起步时间内按 Z / X 也能锁**：锁住的是起步等级，0.3s 到了照常生效。
9. **双蓄 B 方式的条件**：第一发松手时另一只手必须已是有效蓄力，才允许第二发回头替换。撤掉第一发时，已射出的子弹和已生成的特效一并回收。
10. **强化招两只手一起锁**；用哪把武器出由配方上的 Weapon Source 决定（默认：有远程用远程）。
11. **没蓄够 0.3s 就松手不清连段**（旧版会清）。
12. **动画里没有出刀 / 出弹事件的招式**整招按"判定中"处理（等同旧版全程锁移动）。

#### 已知限制
- 时间表按动画 1 倍速计时。Animator 里攻击状态的 Speed 不是 1 的话，判定时间点会和画面对不上。
- 没检查 Z / X 是否已在 PlayerInputConfig.inputactions 里绑了别的功能。
- `OnChargeProgressChanged` 的进度含义从"到满级的总进度"变成"到下一级的进度"，如果有蓄力条 UI 订阅它，表现会变。
- 蓄力准备窗口的移速折扣（preChargeMoveSpeedMultiplier）没动：后摇里按住准备蓄力时移动仍会打折。
